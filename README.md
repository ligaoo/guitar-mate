# 吉他助手 GuitarMate

浏览器里本地运行的吉他工具箱:和弦图、练耳、调音器、自动扒谱、音色分析。
**零依赖服务端、数据不出浏览器**(麦克风录音与练习记录全部本地处理),支持安装为 PWA 离线使用。

## 功能

| 模块 | 说明 |
|------|------|
| 🎸 和弦图 | 12 调 × 12 类和弦的程序化指法生成(约 150+ 和弦、每个多把位);点击试听(Karplus-Strong 拨弦合成);按指法反查和弦名;变调夹换算;收藏;6 种调弦 |
| 👂 练耳 | 音程(旋律/和声)、和弦性质、音阶调式、旋律听写(音级输入)、节奏听辨(网格输入);自适应难度(连对升级/连错降级);正确率与连续练习统计 |
| 🎛️ 调音器 | YIN 音高检测,指针表盘 ±50 音分;标准/Drop D/DADGAD/Open G/Open D/降半音调弦;点弦钮听标准音 |
| 🎧 自动扒谱 | **分轨预处理 + 双引擎可选**:先做音源分离(HPSS 去鼓 + 中侧分解 + 低频切除,离线零模型)再识别;① 内置 DSP(离线、零加载,单音)② Basic Pitch(Spotify 开源神经网络,支持**复音/和弦**,模型 ~1MB 本地内置);起音检测(能量上升约束+抛物线插值+同音伪起音合并)→ 音符分割 → BPM 估计与**残差细化** → **每拍 12 细分网格量化**(直 16 分/三连音/swing 同网格)→ DP 指法推断 → 六线谱;编辑器、谱面试听(变速+节拍器)、**片段循环与 A/B 对比**、**曲库保存/加载**、导出文本 Tab 与 MIDI |
| 📊 音色分析 | 实时频谱(对数频率)+ 声谱图瀑布;单音分析:音准偏差、长音稳定度、谐波结构 H1-H8、奇偶次比、失真度估计、起音时间、衰减、频谱质心/滚降/平坦度;与上次分析对比 |
| 📈 音高轨迹 | 短录音的**逐帧音高曲线**(帧级 YIN,11.6ms 分辨率):纵轴按音名分格、横轴时间;稳定段自动标注**音名+音分偏差**(容忍揉弦,滑音自动阶梯化);悬停查看任意时刻频率/音名/音分;点击曲线从该处播放原音频对照;段落表格可试听每个音 |

> **双引擎说明**:DSP 引擎适合干净的单旋律(秒出结果);Basic Pitch 引擎首次使用需加载 AI 运行时(~2MB,之后浏览器缓存),对和弦扫弦、复杂复音显著更强,灵敏度(起音阈值)可调。
> 合成器测试音色对 Basic Pitch 属分布外输入,识别偏保守;真实吉他录音效果最佳。

## 运行

```bash
npm install
npm run dev      # 开发(自动复制 BP 模型到 public/)
npm run build    # 产物在 dist/,纯静态,可部署到任意路径(相对路径构建)
npm run preview  # 本地预览构建产物(SW/PWA 仅在构建后生效)
npm run host     # 构建并在局域网广播(手机/其他电脑访问打印的 http://192.168.x.x:4173)
npm test         # 算法自测(8 个测试文件:和弦/指法/导出/扒谱/音色/音高轨迹/起音时间/音源分离/BP 后处理)
npm run eval      # 扒谱准确率评估(合成黄金样例 × 引擎 × 输入变体,详见 EVAL.md)
npm run eval:bp   # 同上,只跑 Basic Pitch
```

麦克风功能需要 `localhost` 或 `https` 环境。

## 如何分享给别人

构建产物 `dist/` 是**纯静态文件**(含 AI 模型),四种方式:

0. **GitHub Pages(推荐)**:仓库已带自动部署工作流(`.github/workflows/deploy.yml`),发布步骤:
   1. 在 github.com 新建空仓库 `guitar-mate`(Public,不勾选 README)
   2. 本目录执行:
      ```bash
      git remote add origin https://github.com/<你的用户名>/guitar-mate.git
      git push -u origin main
      ```
   3. 仓库 **Settings → Pages → Build and deployment → Source 选 "GitHub Actions"**(只需一次)
   4. 等 Actions 跑完(约 2 分钟),访问 `https://<你的用户名>.github.io/guitar-mate/`
   之后每次 `git push` 自动重新部署。https 环境全功能可用(含麦克风),可安装为 PWA。
1. **免费托管**:打开 [Netlify Drop](https://app.netlify.com/drop) 把 `dist` 文件夹拖进去,几秒后得到一个 `https://xxx.netlify.app` 链接。Cloudflare Pages / Vercel 同理。
2. **局域网共享(临时)**:本机运行 `npm run host`,把打印的 `http://192.168.x.x:4173` 发给同一 WiFi 下的人。注意:非 localhost 的 http 下浏览器禁止麦克风,调音器/录音不可用,其他功能正常。
3. **自己的服务器/NAS**:`npm run build` 后把 `dist/` 上传到任意静态目录(nginx/caddy/OSS)。**支持部署在子路径**(资源全部相对引用,已验证);配好 https 后麦克风可用。

## PWA

构建产物自带 manifest 与 Service Worker:应用壳、图标、Basic Pitch 模型全部预缓存,**断网可完整使用**。
部署到 https 后可通过浏览器"安装应用"添加到桌面/主屏。移动端为底部导航 + 大触控目标布局。

## 技术栈

React 18 + TypeScript + Vite;音频全部使用原生 Web Audio API:
- **合成**:Karplus-Strong 拨弦物理建模(离线 buffer 生成 + 缓存)
- **音高**:YIN 算法(调音器 / DSP 扒谱 / 音色分析共用)
- **DSP 扒谱**:STFT + 频谱通量起音检测 + 逐帧 YIN + 音符分割 + IOI 直方图测速 + 16 分音符量化 + DP 指法求解,跑在 Web Worker
- **AI 扒谱**:@spotify/basic-pitch(TF.js,动态加载独立 chunk ~1.8MB,主包不受影响),模型本地内置零下载
- **导出**:自实现 SMF MIDI 写入器与文本 Tab 生成器
- **存储**:localStorage(练耳统计 / 和弦收藏 / 曲库)

主包 gzip 约 70KB;AI 引擎为按需加载的异步 chunk。

## 扒谱准确率

**先量化,再优化**:`npm run eval` 用 6 个带标注的合成样例(单声部 / 加鼓 / 加贝斯 / 加人声 /
整曲混音 / 整体偏高),按 MIREX 风格(onset ±50ms 且音高完全相等)算 precision / recall / F1,
并额外给出「音高-only」与「节奏-only」两个诊断指标用于归因。基线与改进记录见 [EVAL.md](./EVAL.md)。

由基线发现的**系统性**缺陷(已修复):

- **DSP 起音时间整体偏晚约 67ms**:分析前给信号补零了 `WIN` 个采样,但「帧序号 → 时间」的换算
  按补齐后的坐标计算,整谱偏移超过 ±50ms 容差(A/B 对比里整谱也晚一截)。修正后实测约 2ms,
  并有 `test-onset.ts` 守护。
- **Basic Pitch 把持续音拆成两段**:同一音高在谱面上被写成两个相邻音符,是假阳性的最大来源。
  新增「同音高、首尾相接」合并后处理(`mergeAdjacentSamePitch`),按音高分别跟踪,
  中间夹其它音高也不断链。
- **Drop D / DADGAD 的低音 D2 被丢**:MIDI 音域过滤原为硬编码 `40..88`,而 Drop D 的低 D 是 38。
  现按当前调弦传入音域边界。
- **DSP 管线只听 0 声道**:扒谱页只把 `getChannelData(0)` 交给 DSP 引擎,硬右声像的内容完全不可见。
  现改为各声道等权求和。

## 第三轮(2026-09-28)

- **YIN 缓冲区复用**:调音器/DSP 管线/音色分析的高频逐帧调用共享暂存区,消除每秒上百次数组分配

## 已知限制

- DSP 引擎对复音(和弦)与强失真音色识别率有限;Basic Pitch 引擎可识别复音,但极端混响/失真仍建议人工修正
- 扒谱测速依赖起音检测,固定速度的单旋律效果最好;可用 BPM 输入与整体偏移手动校准
- Basic Pitch 在 Worker-WebGL 不可用的环境(向日葵/ToDesk 虚拟显示器、远程桌面)自动回退**多 Worker 并行 CPU**(音频分块 × 最多 4 路同时推理,结果与单路一致);**这不是没有 GPU**,是虚拟显示驱动导致 Worker-GL 的推理提交挂死(初始化能过)。拔掉远程控制虚拟屏或在本机屏幕直接使用即可恢复 GPU 加速(约 10 倍速)
- 长谱默认分页渲染(前 8 小节),播放/导出/保存始终包含全部音符

## 第五轮:扒谱准确率评估基线 + 分轨预处理(2026-09-28)

**背景**:整首歌直接扔进去基本不能用。定位后发现不是参数问题,而是管线缺了两个环节
(**音源分离**、**吉他物理约束**),外加若干系统性缺陷。

**本轮完成**:

- **评估基线 `npm run eval`**:6 个带 ground truth 的合成样例(立体声混音,双轨吉他分居左右、
  人声/贝斯/底鼓居中,与真实制作一致)× 引擎 × 输入变体;指标为 MIREX 风格音符级 F1
  (另给音高-only / 节奏-only 用于归因),报告可导出 JSON
- **音源分离 `src/transcription/separation.ts`**(离线 DSP,零模型下载):
  ① HPSS 谐波/打击乐中值滤波(去鼓的宽带瞬态)② 中/侧分解(M/S↔L/R 严格无损,
  掩码对 M 与 S 分别施加,硬左右内容不被误伤)③ 分段整形(切 70Hz 以下,贝斯基频的
  2-5 次谐波正是「高八度幽灵音」的来源)。30s 分块处理控制内存,跑在独立 Worker
- **扒谱页接入**:「🎛 分轨预处理」开关 + 中置抑制强度滑杆(默认 0.6);
  取代原先粗糙的「人声消除」(纯中置相消,会连带干掉居中的吉他)
- **可插拔后端**:`SeparationBackend` 接口已留好,Demucs/htdemucs 模型后端可按同一接口接入
- **测试**:新增 `test-onset.ts`(起音时间回归)、`test-separation.ts`(分离行为契约)、
  `test-bp-post.ts`(BP 后处理);`test-loudness.ts` 改为固定种子,不再时过时不过
- **顺带修掉 3 个系统性缺陷**:BP 持续音被拆成两段、Drop D 低音 D2 被音域过滤丢弃、
  DSP 管线只听 0 声道。详见 [EVAL.md](./EVAL.md)

**实测**(6 个合成样例的宏观平均 F1):

| 输入变体 | DSP 引擎 | Basic Pitch |
|---|---|---|
| `raw` 原始混音(改动前) | 16.7% | 42.7% |
| `sep` 分轨:去鼓 + 去低频 | 22.7% | 41.7% |
| `oracle` 理想分离(标注吉他轨) | 28.3% | 40.7%(精确率 73.6%) |
| `sep-c` 分轨 + 中置抑制 0.6 | 24.9% | 43.8% |

两个引擎在**干净单声部**样例上都到 **99.1%** —— 说明「整首歌不能用」是输入与管线的问题,
不是引擎本身不行。分离买到的主要是**精确率**(伪音符被清掉),而**召回率瓶颈在模型侧**:
即使把标注的吉他轨零串音地单独喂进去,和弦类样例的召回仍只有 19.3%。
所以下一步该换/微调**吉他专用**模型,而不是继续打磨 DSP 分离。

**已知局限**:

- 离线 DSP 分离能有效去鼓、降贝斯、恢复分居左右的吉他,但**无法**把「居中的人声」和
  「居中的吉他」分开——那需要学习型模型。且分离有代价:干净独奏输入上会掉约 2 个点
  (HPSS 掩码会削弱拨弦瞬态),所以是开关而非默认常开。
- **全曲音准偏移未校准**:整体偏高 55 音分时 Basic Pitch F1 从 30.8% 掉到 12.4%。
  吉他录音整体偏 ±10~30 音分很常见,变速翻录更甚。
- **BPM 估计的八度选择不可靠**:100 BPM 的单声部样例被估成 199(八分音符当拍),
  和弦样例被估成 50/164;页面上需用 BPM 输入框 + 整体左右移动手动兜底。

## 第四轮:AI 扒谱长音频卡死修复(2026-09-28)

**症状**:AI 推理到 ~98% 后页面失去响应。**根因**(三层):

1. Basic Pitch 的 `outputToNotesPoly`(melodiaTrick)是 O(音符数 × 帧数 × 频段) 的后处理,3 分钟音频约 10 亿次操作,原先**同步跑在主线程**——推理结束(进度 ~98%)后页面冻结数分钟;此外它先克隆整个帧矩阵,叠加 `concat` 逐批全量复制造成 GC 风暴
2. 长谱一次性渲染:每小节 288 个交互热区 × 几十小节 = 上万 SVG 节点
3. 部分环境(向日葵/ToDesk 等远程控制的**虚拟显示驱动**、远程桌面)下 **Worker 内的 WebGL 会无声挂起**——不是没有 GPU,是虚拟显示器吃掉了 Worker-GL

**修复**:
- **全管线迁入常驻 Web Worker**(推理 + 音符提取都不再碰主线程),模型在 worker 内只加载一次
- **60 秒分块推理**:避免长音频一次性构建数百 MB 帧张量,块间带窗口重叠上下文并裁掉越界帧,进度全局单调
- 批次累积 `concat` → 逐行 `push`(O(n²)→O(n));不再累积不使用的 contours 流
- **阶段感知看门狗**:推理阶段 45 秒无进度(Worker-GL 挂死的特征)自动终止 worker 并以 **CPU 后端重建重试**;`notes` 后处理阶段(纯 JS、本身就要数分钟且无中间消息)不做超时
- **谱面分页**:默认渲染前 8 小节 + 「显示更多/全部」;插入热区仅在启用插入笔时渲染
- 超过 4 分钟的音频提示用片段功能分段扒谱;超时错误给出明确建议文案
